# Native feedback campaign

The serial campaign uses the current retained KiCad board as its parent. It generates finite component pose candidates, previews them on private native copies, and runs the selected candidate through a complete 600-second whole-board Freerouting evaluation. It is a heuristic selector, not a trained model.

`copperhead_campaign.py` reuses the existing attempt records, loop feedback, scar store and stage-one runner. It excludes failed poses already evaluated on the exact parent. Native preview ranking penalizes removal of copper features implicated in earlier failed attempts, other-net collision removals, and splits of previously connected native pad groups before using approach distance. The selected proposal records the actual feedback attempt IDs and the selection artifact. A rejected attempt never becomes the next parent.

The R71 trial `stage1-20260913-051302-44022a` supplies measured negative feedback: its full route increased native opens from 53 to 56. It split the previously connected R71.2/U3.50 group and the four-pad CH2_SBU2_IGN group. The original attempt and collision records are preserved. A subsequent unsaved native connectivity audit enriched the feedback before the next selection; this does not imply that R71 was generated by the newer selector.

Final retention additionally requires no previously connected native pad group to split. A reduced aggregate open count cannot compensate for a newly broken existing connection. Manufacturing categories remain guarded regardless of severity. The separate manufacturing-repair selection can retain a strict physical-rule improvement without a noisy airwire proxy veto, but requires unchanged support files, complete backend execution and preserved native connectivity.

The additional through-via experiment adds a separate `Via[0-5]_450:200_um` padstack and routing eligibility. It preserves all existing padstack definitions, wiring expressions and original project rules. Both fanout and the subsequent fresh full-routing DSN export receive the added definition. Native checks independently compare every old via site, net, diameter, drill and span; the new option being loaded is not evidence that it was instantiated or improved routing.

Run the existing supervisor with a reviewed candidate catalog and a deadline:

```sh
.venv/bin/python scripts/copperhead_campaign.py \
  --until 2026-09-13T09:25:00-07:00 \
  --route-seconds 600 \
  --catalog .local/copperhead/campaign/reviewed-catalog.json
```

The catalog can supply exact finite pose hypotheses or explicit terminal fanout actions. Once reviewed poses are evaluated, the selector ranks passive components touched by current native missing connections and searches bounded translations and rotations. Each complete route updates persistent feedback for the next selection. Native preflight copies and every selection trace remain available, including unsuccessful alternatives.

Validation at the first deployed selector checkpoint: 72 tests passed, one skipped; the Java fanout wrapper compiled against the actual installed Freerouting JAR. Native board outcomes and final engineering qualification remain independent of these software checks. The current board is still incomplete and receives no official score.
